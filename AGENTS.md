# AGENTS.md

Operational guide for AI coding agents working in this repository.

`README.md` is the user-facing source of truth for installation, configuration,
the multi-locale model, and deployment. This file records the commands, invariants, and
pitfalls an agent needs in order to change the code safely. If the two disagree, prefer
`README.md` and the code, then fix this file in the same change.

Last verified: 2026-10-17 against theme version 3.2.1.

## What this repository is

A Ghost 6 Handlebars theme for sredevops.org. Ghost renders every page on the server;
Vite 8 (Rolldown) builds CSS/JS and React islands add interactivity only where a
template declares a mount point. Tailwind CSS v4 runs through `@tailwindcss/vite`.
The publication is multi-locale: `routes.yaml` defines `/en/`, `/es/` and `/br/`
collections, and per-post `custom-*.hbs` templates set the document language.

There is no client-side router, no Gulp, no PostCSS config, and no
`tailwind.config.js`. Do not add them.

## Environment

- Node.js `>=24` (CI uses Node 24).
- Yarn `1.22.22`, pinned by `packageManager`. Use `yarn`/`yarn.lock`; do not run
  `npm install` or `pnpm` (they create a second lockfile and drift from CI).
- Ghost `>=6.0.0` is needed only for local visual/fixture checks, not for the build.
- The build itself makes no network requests: fonts and icons are committed, and
  Prism is bundled from `devDependencies`. Do not add a build step that downloads
  from the network.

```bash
yarn install --frozen-lockfile   # exactly what CI installs; fails on a stale lockfile
```

## Commands

| Command | Purpose |
| --- | --- |
| `yarn dev` | `vite build --watch`: rebuilds `assets/built/**` and the manifest partials on save |
| `yarn build` | One production build into `assets/built/` |
| `yarn verify` / `yarn test` | The full offline gate: build + GScan + ship manifest + unit + bundle + class coverage |
| `yarn test:ci` | Plain GScan only (despite the name) |
| `yarn test:dev` | Verbose GScan |
| `yarn test:ship` | `scripts/ship-manifest.mjs --check` (package contents + asset references) |
| `yarn test:unit` | `node:test` suite for models, helpers and `enhance` islands |
| `yarn test:bundle` | Loads the built entry and checks the island/code-splitting contract |
| `yarn test:classes` | Every class in a template or island has CSS in the build |
| `yarn test:sec-feed-layout` | Chromium layout checks for the security-feed panel (needs Ghost + feed) |
| `yarn package` | Writes and validates `dist/<name>-<version>.zip`; keeps older archives |
| `yarn ghost:up` / `ghost:down` / `ghost:restart` / `ghost:logs` | Local Ghost 6 + MySQL stack on port 2368 |
| `yarn fixtures:capture` / `normalize` / `diff` / `promote` | Golden-HTML fixture workflow (needs a seeded Ghost) |
| `yarn sync:fonts` / `sync:icons` | Regenerate committed fonts/icons and licence texts (network) |

Rules of thumb:

- Run `yarn verify` before claiming a change works. `test:bundle`, `test:classes` and
  `test:ship` need a fresh build; `yarn verify` builds first.
- Do not add `--fatal` to GScan. It only fails on fatal findings, so error-level issues
  (removed helper, empty translation) would pass CI while Ghost logs them at boot.
- GScan is pinned in `devDependencies`; do not switch to a globally installed version.
- Run `git diff --check` too (the pre-commit config also runs gitleaks, an EOF fixer,
  private-key detection and a submodule check).
- After editing any `.hbs` file, run `yarn ghost:restart` before trusting the local
  site; Ghost caches compiled templates.

## Architecture contracts

### Rendering and locales

- Locale collections are defined in `routes.yaml`. A post belongs to a collection only
  when it has exactly one of the tags `en`, `es`, `br` (each filter negates the other
  two). `hash-*` tags are legacy; never add them.
- Root `/` is intentionally an unfiltered, mixed feed.
- Two different values, do not conflate them:
  - `documentLang` — BCP-47 value for `<html lang>` (`en`, `es`, `pt`).
  - `locale` — the theme's content key used in filters and partial arguments
    (`en`, `es`, `br`). Brazilian Portuguese uses `br`, not `pt`.
- `default*.hbs` are one-line wrappers around `partials/shell.hbs`; `home*.hbs` extend
  the matching shell and render `partials/collection-layout.hbs`; `custom-*.hbs` extend a
  locale shell and render `post-layout` or `page-body`.
- The document language is chosen by the template the editor selects in Ghost Admin, not
  inferred from tags. There is no automatic tag-to-template inference.
- Partial hash arguments do **not** survive `{{#post}}`, `{{#page}}`, `{{#get}}` or
  `{{#foreach}}`. Pass `locale` at the partial's top level or as a literal at the call
  site.
- Adding a locale means touching wrappers, `routes.yaml`, shared locale branches, a
  translation file and fixtures; follow the step-by-step list in `README.md`.
- Known gaps (do not "fix" by guessing): no Portuguese page custom template
  (`custom-page-br.hbs` does not exist); Ghost's own `{{t}}` strings follow the
  publication language, not the page; tag/author cards use English date/reading-time
  strings because those routes have no locale context.

### Assets and the Vite build

- `vite.config.js` is deliberately Ghost-safe: `base: "./"`, `publicDir: false`,
  `outDir: "assets/built"`, `assetsDir: "."`, manifest on, and
  `build.rolldownOptions` (Vite 8 / Rolldown; `rollupOptions` is deprecated).
- Never hardcode hashed asset filenames or edit `assets/built/**` by hand. Templates load
  assets through `{{asset "built/..."}}` inside the generated
  `partials/vite_assets/{head,foot}.hbs` files.
- After a build that changes assets, commit the regenerated manifest partials. They are
  generated but tracked because a theme must parse before its first build.
- Do not add a `public/` directory; static files live under `assets/`.
- `assets/js/index.js` imports the CSS entry, `main.js` and the island runtime. The entry
  must stay framework-free; React is pulled only by the island chunks that use it.
- Prism imports must keep explicit `.js` extensions (e.g. `prismjs/components/prism-bash.js`).
  `tests/code-blocks.test.mjs` enforces this because Node's ESM loader imports the
  sources directly.

### Islands

- An island module exports exactly one of:
  - `mount(element, props)` — owns dynamic UI and renders into the element;
  - `enhance(element, props)` — augments existing server markup, loads no framework, and
    may return a cleanup function.
- Register it in `assets/js/islands.js`; the registry key must equal the template's
  `data-island` value. Props come from `data-*` attributes.
- Mark below-the-fold islands `data-island-lazy`; the runtime observes them with
  `IntersectionObserver`.
- Nothing may break with JavaScript disabled. Mount points are empty containers; the
  security feed provides a `<noscript>` link.
- Do not put user-visible strings in JS when they can come from
  `partials/island-config.hbs` (`{{json}}` + `{{t}}`, read with `t()` from
  `assets/js/lib/theme-config.js`). That payload is inline on every page.
- Keep island Tailwind classes real: `yarn test:classes` fails otherwise.

### Styling

- Tailwind v4 has no JS config. Theme tokens and `@source` globs live in
  `assets/css/index.css`; component styles live in `assets/css/theme.css`.
- Name tokens by role (`bg-surface`, `text-muted`, `border-border-strong`), never by
  colour. Each token is a `light-dark(light, dark)` pair; dark is the default and the OS
  preference is not consulted.
- Fonts and icons are self-hosted. Do not reintroduce Font Awesome, Google Fonts, or any
  third-party host: `tests/no-third-party.test.mjs` fails the build. The optional
  security feed is the only permitted cross-origin request, and its origin may come only
  from the `sec_feed_api_url` setting.
- `assets/css/fonts.css` is generated by `yarn sync:fonts`; edit the script or its source
  files, not that CSS.

### Ghost compatibility and theme settings

- `package.json` is also the Ghost theme manifest. Keep `config`, `image_sizes`, `gpm`
  and the `engines` fields valid.
- Custom settings are append-only. Keys are `snake_case`; never rename the existing
  `show_search`, `show_login`, `sec_feed_*` or `featured_*` keys, because Ghost stores
  values by key. Descriptions must stay under 100 characters. Homepage options use
  `group: "homepage"`.
- `{{img_url size="..."}}` values must match a key in `config.image_sizes`.
- `{{ghost_head}}` stays before `</head>` and `{{ghost_foot}}` before `</body>` in
  `partials/shell.hbs`; templates are wrappers and must not duplicate them.
- Translation keys live in `locales/*.json`. Keep the three files aligned.

### Packaging and release

- `scripts/ship-manifest.mjs` is the only inclusion rule. A theme zip ships root
  templates, `partials/`, `locales/`, `package.json`, `LICENSE`, `routes.yaml`,
  `assets/built/`, `assets/vendor/` and static assets. It must not contain
  `assets/css`, `assets/js`, `lib/`, `scripts/`, `tests/`, `docs/`, `node_modules/`,
  config files, or font sources.
- Never zip the repository by hand. Use `yarn package`; it runs the manifest check, writes
  `dist/<name>-<version>.zip`, and validates the archive with `gscan --zip`.
- Older archives in `dist/` are kept for rollback on purpose. Do not delete them.
- Do not bump `version` or edit `CHANGELOG.md` unless the task is a release. When it is,
  follow `docs/release-checklist.md` exactly.
- Do not trigger the `deploy-theme` workflow, create tags, or publish releases unless
  explicitly asked. That workflow is `workflow_dispatch` and restricted to the
  `ngeorger` account; it needs `GHOST_API_URL` and `GHOST_ADMIN_API_KEY` secrets.
- `main` is protected. Work on a feature branch and open a PR; never force-push or bypass
  branch protection.

## Change workflows

**Template or partial change**

1. Edit the `.hbs` file; keep inheritance `{{!< ...}}` at the top and pass `locale`
   explicitly.
2. `yarn build` if assets changed, then `yarn ghost:restart` for the local site.
3. `yarn verify`.
4. If you touched shared markup, run the fixture flow against a seeded Ghost and explain
   every diff: `yarn fixtures:capture && yarn fixtures:normalize && yarn fixtures:diff`.
   Promote baselines with `yarn fixtures:promote` only after reviewing the diff.

**CSS, font or island change**

1. Edit `assets/css/**` or `assets/js/**`.
2. `yarn build` — this also rewrites the manifest partials; commit them.
3. `yarn verify`, and `yarn test:sec-feed-layout` if the security-feed layout changed.
4. Verify the page still works without JavaScript where relevant.

**Dependency or build tooling change**

1. Update `package.json` and `yarn.lock` together.
2. Keep Vite 8's `rolldownOptions` shape and Tailwind v4's Vite plugin.
3. Rebuild, check the generated partials, and run `yarn verify`. Note that Yarn 1 emits
   known cosmetic warnings (Ghost engine field, Handlebars resolution, cache path); do not
   "fix" them by changing package managers.

**Documentation change**

`README.md` is authoritative for users; `docs/adr/` records decisions;
`docs/release-checklist.md` is the release runbook; `tests/fixtures/README.md` covers
the local Ghost setup; `docs/v3-roadmap.md` is historical context. Update the relevant
document when behavior, commands or settings change, and keep `AGENTS.md` in sync.

## Avoid

- Editing `assets/built/**`, `dist/**`, `node_modules/**`, or the generated
  `partials/vite_assets/*.hbs` by hand (regenerate instead).
- Hardcoding asset URLs, API origins, or locale-dependent strings.
- Renaming Ghost custom settings or image-size keys.
- Adding a client-side router, moving page rendering into React, or making rendering
  depend on JavaScript.
- Adding third-party requests, a second package manager, a second lockfile, or a
  network-dependent build step.
- Committing `.env`, secrets, local Ghost content, or archives.
- Running `git commit --amend`, rebases or force-pushes on shared branches without being
  asked; do not rewrite history that was already reviewed.
- Bumping the version, publishing, deploying, or deleting rollback archives without an
  explicit request.

## Verification checklist before handing work back

- [ ] `yarn verify` passes (or the failure is explained and unrelated to the change).
- [ ] Generated manifest partials were rebuilt and committed if assets changed.
- [ ] `git diff --check` is clean.
- [ ] Template changes were exercised against a local Ghost, or the reason they were not.
- [ ] Docs/README updated when behavior, commands or settings changed.
- [ ] No secrets, `dist/`, `assets/built/` or unrelated files in the diff.
